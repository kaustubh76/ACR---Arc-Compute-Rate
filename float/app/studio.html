ACR Float · what Arc Studio did

Three runs, traced — one that built something, one that refused, one that caught a drift. Every id below identifies a real run and every answer is quoted from the JSON arc-studio run wrote, saved under float/studio/traces/.

The three claims, stated narrowly

compilesThe treasurer writes a sentence; Studio emits the policy JSON. Its output is checked, not trusted — our validator refuses an invalid config before a transaction is built, and the chain keeps the last good policy.
auditsThe vault, including the human-checkpoint path, with findings triaged in commits that name the audit.
holdsThe dashboard, byte-identical — shasum the local file and arc-studio cat the workspace copy and compare.
did notWrite the vault, the tests, the keeper, the agents or the dashboard. It wrote walk.html and venue.html beside them, which is a different and narrower claim.

run 0 · the build — English in, policy JSON out

“Freeze the agent called waster. For everyone else, never pay more than 1% above the ACR fair price, keep two days of forecast spend liquid, and keep all of the idle float in the working vault.”  — with float/policy.schema.json attached, asked for JSON only
It emitted bufferHours 48, maxPremiumBps 100, humanMaxPremiumBps 100, maxPrintAge 1800, workingShareBps 10000, and one agent: waster, frozen: true.

then our validator checked it, which is the actual claim

verdictvalidate() from float/src/policy.ts returned ok = true. It passes because the contract requires an approval ceiling to widen or equal the automatic band, never narrow it — and 100 ≥ 100 holds.
vs chainSeven of eight fields match the live vault exactly — premium 100, print age 1800, bands 1500/1000, working share 10000, buffer 48h, ticket $1.

the one field that differs, and it is arguable

Studio set humanMaxPremiumBps to 100; the deployed policy says 2000. The treasurer's sentence says “never pay more than 1% above the ACR fair price” and says nothing about what a human may approve. Studio read “never” as binding the human too, and capped the approval ceiling at the same 1%. The deployed policy lets a verified human go to 20%. Studio's reading is arguably the more faithful one, and the sentence is the thing at fault: it does not say. It also emitted only waster, the one agent it was told about, where the committed artifact carries scout too.

This is what “compiles the policy” is worth as a claim: a sentence in, a validated config out, one honest disagreement about an ambiguity, and a validator standing between the model and the chain.

run 1 · it refused, rather than guessing

“Read the Float treasury policy at float/studio/policy.generated.json in this workspace and tell me, in two sentences, which agent is frozen and what the fair-price band is. Do not change any file.”
“I can't answer this, because float/studio/policy.generated.json isn't in the workspace. There is no float/ folder at the root, and a search of the whole sandbox found no file named policy.generated.json.”

The prompt was wrong — that path is in the repository, not in the Studio workspace. The useful part is what the agent did with a question it could not answer: it searched, found nothing, and said so. A trace of a refusal is worth more than a trace of a success, because it is the case where a model is most tempted to invent.

run 2 · the same question, with the file sent

“Here is the Float treasury policy this repo deployed. In two sentences: which agent is frozen, and what is the fair-price band in percent? Do not change any file.”  — sent with -f float/studio/policy.generated.json:policy.generated.json
“The agent waster is frozen ("frozen": true); scout is not. The fair-price band is 10% below to 15% above fair (lowerBandBps 1000, upperBandBps 1500), which is separate from the 1% maximum premium (maxPremiumBps 100). This is what the file says, not the live chain. Earlier today the vault showed the scout's daily cap as $60, while this file says $25.”

what it caught, unprompted

It was asked about the freeze and the band. It answered both correctly, then volunteered two things nobody asked for: that a file is not a chain, and that the committed policy.generated.json says a $25 daily cap while the live vault says $60. That second one is a real drift and it is independently checkable — cast call <vault> 'agentOf(bytes32)' $(cast keccak "scout") returns a 60000000 cap. The artifact is a record of what Studio compiled on 2026-11-06; the chain has moved since. Neither number is wrong, and nothing in the repository said so until the agent did.
